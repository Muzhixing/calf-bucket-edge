# 回零反馈候选的上位机衔接

本候选对应 MCU `codex/startup-homing-20261122`，基于 `e58f9dc`。未部署到 RK3588，未烧录 MCU，不改变现有检测/跟踪算法。

行为：

- 解析原 20 字节 v1 状态新增的 bit6/7（B/C 驱动反馈新鲜）、结果7（回零验证不满足）、故障5（运行中零位依据丢失）。这些新鲜位本身不代表回零完成。
- 原固件停在 C=10 的工作位置仍兼容。只有新反馈明确有效、B/C 零位已验证、航向有效、A=75/B=0 时，才接受 C 位于0～10 mm的准备状态。
- 自动模式出现新鲜目标后，先保持 A75/B0、单独将 C 移到10 mm；位置回传到达并收到禁用确认后，才进入原 A/B 跟踪。C 准备过程中目标丢失或用户停止仍会发送禁用；中断后可从有效的当前位置继续，不重新清零。
- 唯一启动故障为通信故障1时，仅在新驱动反馈、零位及航向有效、整个预检机构已停止、命令计数与 UART 错误计数稳定时发送一次禁用确认；等待计数和状态确认成功才继续。其他故障不自动清除。
- 配置中的 A 启动目标更新为75，同时明确标记硬件验收未完成。界面增加准备状态提示；不会重新绘制居中圆。

固件侧仅观察驱动器现有回零，不发送驱动回零命令。缺少 CAN 接线或兼容协议时保持未就绪；仅复位 MCU 后收到空闲也不会确认零位。需要现场确认两个驱动器协议、模块、地址、接线和回零终点。完整接线与烧录验收说明随 MCU 候选包提供。

主机模拟验证（不接设备）：

```sh
PYTHONPATH=deploy/vision_cpp/tracking <python-with-opencv-numpy> -m unittest discover -s deploy/vision_cpp/tracking/tests
SANITIZE=1 python3 <MCU-project>/tests/run.py
```

测试包含启动位置拒绝、反馈缺失、故障分类、C 准备、取消、部分行程续移、原固件兼容，以及原遮挡暂停/居中保持回归。模拟串口通过不代表机械运动已验收。

2026-11-22 验证结果：上位机全套 135 项测试通过，其中新增启动集成9项；包含自动 C 准备→A跟随→遮挡暂停→居中保持。MCU 的5个测试程序在 ASan/UBSan 下通过；GNU ARM 编译及98项中断向量、A75初始化数据、HEX/BIN一致性检查通过。ST HAL 和原 Servo.c 的5条既有编译警告保留，未引入新警告。未进行物理串口、烧录或实机运动测试。

# 近距离大目标连续性修复

关键问题：车辆已在约20cm确认距离，为何继续前进到正左侧时反复失锁，未执行侧移和伸臂？

## 证据与机制

实车轮次`manual_20261126_183949_28179`在53.9秒时确认距离0.2108m、A112°，生成前移约103.7mm、侧移约91.7mm、B回顶、C伸150mm计划；随后继续正左对齐，在A126°附近反复丢失目标。最后有效框`[86,140,1144,716]`，之后检测框扩展至`[120,76,1208,719]`，约占画面的76%。

两个独立问题共同造成持续停等：

1. `visible_detection_box()`沿用了普通完整目标的70%面积门槛。真实近桶一旦超过该面积，即便左右边界都可见且模型持续检出，也会被整体过滤。板端原版对同一组51帧均未恢复目标。
2. 截断追踪恢复初始化仍执行GrabCut和完整像素先验构造。板端测得一次初始化约136ms，其中前景权重105ms；加上取图延迟后，下一个有效帧间隔达到168ms，超过现有160ms连续性要求。恢复后可立即再次失锁。

## 修复设计

近距离大框仅在左右边界仍完整可测时进入原有截断追踪。其内部使用完全位于当前检测范围内的可见像素，并通过纵向裁取保持普通追踪器的70%像素预算；原始检测框单独保存，水平方向仍由原始左右边界计算。没有重建图像外桶中心，也没有扩大普通完整目标的合法范围。整幅画面大框、横向边界不明的大框、越界及细小区域继续拒绝。

截断追踪依赖每帧当前唯一检测，初始化及其恢复参考使用空间权重先验，不在连续性时限内执行GrabCut；普通完整目标仍执行原有前景分割。先验使用广播生成，避免建立两个完整坐标网格。现有外观、同像素几何、帧间隔、目标身份、航向和串口保护要求保持。

## 检验

- 相同51帧实拍输入：原版0个有效目标；修复版第0.201秒恢复原身份1，之后45帧全部有效，仅恢复一次。
- 板端实时图像10秒：258个观察中256个有效，首个恢复约0.268秒，此后未再失锁；处理耗时95分位约45ms。
- 主程序实际`Observer`，包括双目原图取图、标定重映射、日志与预览写入：20秒内253个有效观察全部保持目标，无恢复、无错误。使用新鲜同场景种子检验连续追踪；另一项51帧检验独立验证历史身份恢复。
- 使用上述真实观察输入的影子对齐检查，在合成A131°与已停车条件下，0.448秒通过正左对齐入口。角度和停车是模拟条件，未移动实车，也不能据此宣称底盘位移或C伸臂已验收。
- 新增回归覆盖：超过70%的桶框、检测高度抖动、完整目标面积门槛保持、截断初始化与恢复不执行分割、错误/歧义/缺失/过时目标拒绝，以及正左角度和停车确认前不能进入下一阶段。
- 全量380项检查：372项通过，8项因环境条件跳过；随后增加的对齐组合用例随7项针对性检查全部通过。Ruff、格式、wheel构建及板端110文件清单校验通过。

所有板端检查均为只读视觉检查。实际`Observer`检查还在进程内禁止打开控制串口，未发送机构或底盘指令。

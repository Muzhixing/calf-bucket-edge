# B/C 最高设定速度自检与追踪准备

固定8秒软件检查之后，先完成原有A自检（0°→160°→73°，B/C保持0）；再保持A73°，先让B以最高设定速度下降到96mm并返回0（C保持0），然后让C伸出到100mm并返回0（B保持0）。每一段均等待实际步进结束、稳定到位及禁用确认。最后一次停用确认后才开放新画面自动追踪。工作上限读取arm_reference.json，不使用估计的机械底部。

B/C使用2026-11-24已烧录的并行固件93c31b1。上限分别12.5mm/s和31.46mm/s，加速度分别25mm/s²和78.64mm/s²；原串口协议没有速度字段，每次有限移动由固件直接使用这个速度包络。起步和到位减速保留，短距离达不到匀速上限是正常现象。

B全程的脉冲仿真约8.27秒，不能继续套用原先8秒的A动作超时。新动作超时取两轴各自路程/上限速度＋加减速余量的较大值，再加3秒通信/稳定余量，最少8秒；这不改变前面的8秒软件检查。

实际追踪时，B的大偏差纠正使用完整估计位移，不再统一乘0.7；近目标仍保留0.7阻尼，每段最多24mm。24mm足以达到当前固件的最高B速度，不为追求最高速度人为增大目标位移。保留圈内停调、遮挡暂停、饱和保持和A优先但B不被饿死的发送调度。C仍不自动追踪，仅自检往返和手动行程开放。

固件并行能力必须在配置中声明，未配套确认的固件配置不能启用本次B/C速度自检；本设备配置依据已完成的Flash读回及5mm并行验证更新。串口不能报告固件版本，换回旧固件时必须同步恢复配置。已登记零位的现场状态可以沿用，不发送重复零位登记；普通串口重连或已完成周期的程序重启不会重跑流程。中途取消、丢失回传或故障则停用并保留未完成状态，不自动继续下一段。

此修改保留板端11月24日已有的沿用零位恢复流程，将其纳入仓库；测试同时覆盖Linux独占串口关闭交接。验收记录见outputs/bc_startup_selftest_20261124，实机结果在完成后追加。

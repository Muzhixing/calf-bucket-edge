# ARM构建与异常复核

核心命题：完整视觉程序可以在本地构建为Linux ARM64程序；组件异常不会绕过应用的运动门控；正常A/B决策沿用原追踪控制器。

## 构建结果

在macOS Apple Silicon主机上使用Docker Linux ARM64环境，CMake显式选择`aarch64-linux-gnu-g++`工具链，完成完整`vision`程序的编译、链接和安装。此方式在ARM Linux容器中执行ARM编译器，不宣称验证了x86上的另一套交叉工具链。

- Ubuntu 22.04、GCC 11.4、OpenCV 4.10.0、OpenSSL 3.0.2、GLib 2.72.4、libdrm 2.4.113。
- 这些主要版本与2026-11-25保存的板端CMake构建记录一致；本轮没有连接板卡重新查询系统。
- ELF为AArch64，加载器`/lib/ld-linux-aarch64.so.1`，RUNPATH为`$ORIGIN/lib`。
- 完整源码编译、链接无警告。SDK头文件与运行库来自本地已保存副本，摘要保存在构建记录；不把供应商库提交到源码分支，也不替换板端RKNN运行库。
- 构建脚本、固定OpenCV源码摘要和工具链位于`tools/build/`。构建容器不映射硬件设备，编译和测试运行时禁用网络。

原生程序、私有OpenCV库和Python wheel在本机`outputs/arm_release_20261126/`。它们是构建产物；模型、标定、辅助测距库仍需按完整发布手册显式组装。

## 审查与修正

| 发现的边界 | 最终行为 | 验证 |
| --- | --- | --- |
| 行进任务的Session没有直接标记为active，视觉故障可能只更新页面 | 活动任务检查共同能力依赖；模型/相机等失效请求正常停车，超时保持停止未确认 | 模型失效触发SIGTERM且只请求一次；未退出时锁存 |
| 组件清理抛异常可能离开重查外壳 | 先通知控制会话停止；清理异常变成状态，拒绝重新初始化，网页继续 | 注入进程退出超时，真实HTTP健康端点仍返回200 |
| 初始化期间的停止意图可能丢失 | 应用级停止锁存跨会话发布保留；根目录STOP文件继续生效 | 初始化前停止、换会话、文件存在/移除与恢复拒绝用例 |
| 控制周期中状态可能在计算目标后变化 | 发送目标前再次检查健康与停止状态；保持原控制计算和串口事务 | 原回归、180条原决策对照及运动故障用例 |
| JPEG编码失败、追踪异常或状态文件写入失败缺少清楚状态 | 对应组件报告失败；画面输出与检测分开；记录失败暂停运动 | 编码失败时页面和检测继续，恢复后视频恢复 |
| 任务日志异常数据影响新鲜度 | 跳过结构不合法或过期回传，不以历史日志刷新正常状态 | 无效JSON结构及旧回传后接新回传 |
| 重启视觉进程后原生输出目录改变 | 显式传入追踪叠加文件路径；兼容独立原生程序的原默认路径 | 完整程序编译及应用与原生进程联合回放 |

同时保留：只读串口探测、原有零点账本、单串口写入者、原协议命令格式、停止ACK确认，以及静止/行进任务对同一TrackingController的复用。

## 检验结果

- Linux ARM64完整回归323项，无失败，6项可选CSRT跳过；两项Linux串口用例已实际执行通过。
- macOS重点回归28项通过；180条重构前A/B决策逐项一致。
- 通用C++工作进程测试覆盖初始化异常、推理异常、崩溃、卡死、恢复及限定时间退出。
- 对编译后的完整`vision`程序运行三组合成双目回放：缺标定、标定摘要错误、模型摘要错误。每组取得至少3个不同帧号，图像尺寸和原始双目像素保持正确，组件故障字段可解析，进程正常退出。
- 同一原生程序与Python应用联合回放：模型错误时，页面、视频继续；检测不可用；机构控制禁用；未连接控制器的电机状态为未知。
- Python静态与格式检查、JavaScript语法检查、wheel构建及从独立目录加载检查通过。

验证资料保存在`outputs/arm_release_20261126/`：`native_build.log`、`linux_regression.log`、`focused.log`、`native_replay_final/result.json`、`validation_summary.json`及`source_manifest.json`。

检验支持软件构建、故障隔离和既有控制决策保持。回放不调用真实NPU推理，不访问相机或电机；不能据此确定新增进程通信的实机时延或车辆停止距离。

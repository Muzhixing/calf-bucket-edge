# 正式控制台白色布局

按已确认样稿接入正式控制台：纯白背景，左侧大画面，右侧启动检查与运动控制，画面下方展示帧率、目标纵深和X/Y偏差。检查列表使用`[ OK ]`、`[FAIL]`、`[WAIT]`、`[SKIP]`；没有重放动画、场景选择、样例图片或默认模拟读数。

## 数据含义

| 读数 | 正式来源与规则 |
| --- | --- |
| 画面帧率 | 浏览器实际收到并解码的不同`X-Frame-Id`，按最近2秒计算；重复取得同一帧不计作新帧。与模型/追踪处理帧率分开，检测故障不使有效视频的帧率归零。尚未形成统计或视频过期时显示`—`。 |
| 目标纵深Z | `distance_m`，原生检测所选桶身采样区域的相机前向Z，单位m。只接受`distance_kind=camera_forward_Z_bucket_body`及有效源帧，测距`new/held`有效期1.5秒；计入元数据发布和轮询后的时间。不是机构行程，也不是相机到目标的欧氏距离。 |
| X/Y偏差 | 当前`tracking.target.offset_px`，单位px，相对1280×720画面中心，右/下为正。目标及来源帧超过0.4秒、缺失或检测能力失效时显示`—`。不以另一检测框代替当前追踪目标。 |
| 机构位置 | 原回传的A角度、B/C毫米位置，缺值、回传过期或不能建立新鲜度时显示`—`；不把健康表中较新的串口回传当成旧位置的新时戳。 |

纵深对应原生检测所选桶，偏差对应追踪会话的目标。两者的来源说明保留在诊断详情中；没有引入目标匹配或控制策略。

这些有效期仅用于显示，沿用后端既有0.4秒观察、1.5秒测距和0.7秒回传预算；未改变后端控制阈值。

## 状态与功能

检查行直接消费`health.components`。等待初始化/恢复显示WAIT，明确不可用/过期显示FAIL；串口不可用时，无法确定机构及四轮状态显示SKIP。正常初始化期间预期的控制器未就绪可显示WAIT，明确控制器故障仍显示FAIL。机构OK标为“回传就绪”，不声称具有协议尚未提供的独立电机在线证明。

重新检查、启动/停止、自动识别、实时框选/取消、旧步进模式底盘隔离确认、启动阶段/倒计时、机构位置、诊断及运行日志均保留。诊断内容折叠，保持主界面简洁。按钮可用性、请求令牌、命令体、框选前停止及快照提交、heartbeat、pagehide和停止未确认门控的代码保持。

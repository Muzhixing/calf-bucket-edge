## 先验收视觉与降级

以`./run_track.sh --observe-only`开始，记录发布清单、模型/标定摘要、程序日志和页面状态。

| 条件 | 预期 |
| --- | --- |
| 板卡+摄像头，无STM32 | 页面与实时画面持续更新，真实模型检测可用；串口不可用，A/B/C及四轮状态无法确认 |
| 测试副本中的模型缺失/损坏 | 页面和视频继续，检测不可用，恢复方式明确；无运动 |
| 测试副本中的标定缺失/损坏 | 原始画面继续，标定及依赖能力不可用；无定位控制 |
| 摄像头断开后接回 | 页面不退出，过期画面不继续提供；恢复画面后健康状态更新 |
| 点击重新检查或初始化期间点击停止 | 状态服务在线；设备恢复不能自行解除运动暂停 |

更改资产仅限测试副本；修复资源后重新检查。清单发现资产变化属于预期故障，不是绕过校验的理由。

## 再验收既有控制

在已有物理零位和正常设备状态确认后，使用正常控制入口检查原8秒启动窗口、一次零点登记、A/B跟随、居中保持、边界及目标暂失恢复。观察模式不会开放运动按钮，控制测试需明确退出观察模式并按既有现场流程启动。

通信中断后，页面应显示问题并锁存运动。没有新的禁用确认时必须显示“停止未确认”；接回通信不能自动续跑，也不能重复登记零点。核对停止命令与对应ACK，而非只根据页面或进程退出判断停止。

行进任务额外核对：A/B调整与底盘互锁、前进至靠近的串口所有权交接、阶段日志新鲜度、根目录STOP文件、总时长/驱动预算和正常禁用确认。模型/NPU正常推理下记录帧率、延迟、内存和恢复耗时，比较原基线。

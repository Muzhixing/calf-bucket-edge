# 0.3.1 合并前检查

本阶段检查架构重构后是否仍只维护一套追踪控制，任务生命周期是否正确保留串口回传与禁用确认。静止与行进共用 `TrackingController`，未重新实现 A/B 算法；本次不修改模型、标定、速度或固件。

## 发现并修复

1. 初始目标未出现时，任务外壳已经释放只读串口监视器，任务却等到锁桶后才打开串口。超过交接窗口就会误报通信丢失。现在运动任务在等待目标前完成当前姿态检查和禁用握手，并持续读取回传；没有目标时不发送使能命令。观察模式仍不打开运动端口。
2. 总运行预算耗尽后，每次监督循环都会再次发送 SIGTERM，可能反复打断控制器的正常退出。现在预算只锁存故障，由原有单次停止通路发送信号并等待确认。
3. 重新检查/应用退出清理原先只等任务进程结束，没有再次要求禁用确认。现在清理读取任务终态；缺失或未确认就锁存 `STOP_UNCONFIRMED` 并拒绝重新初始化。正常退出返回码也反映清理结果。

前两项新用例在修复前分别复现“无目标期间0条回传”和“三次监督发出4次终止信号”。修复后无目标期间持续接收、全部命令禁用，超时只发一次终止信号。退出用例同时覆盖无确认拒绝清理和有确认允许清理。

# 本轮改动与验证（2026-11-26）

建立的行为：组件缺失或失败时，应用按依赖关闭相应能力，继续提供网页及其他可用功能。控制器通信恢复不代表允许自动恢复运动；停止未确认时保持服务端锁存。

## 已落实

- `track`、`mission`及旧任务脚本使用共同的常驻应用外壳。旧任务模块只保留参数构造，移除了重复的进程启动/监控实现。
- 相机、模型、标定、机构配置、串口、机构、底盘、测距、日志具有共同的健康状态和能力依赖。
- 原生推理独立子进程，处理加载错误、推理错误、崩溃、超时及退避恢复；原生后端失效时可退到原始画面进程。
- HTTP先启动，后台加载视觉和控制组件；缺少可选Python依赖时也能显示状态页。
- 前端展示组件问题、恢复方式及受影响的能力。过期画面不继续输出，过期位置不继续显示为有效位置。
- 观察串口只读；机构执行和启动端口使用明确注入的串口路径。任务阶段交接后切换到当前阶段回传日志，旧日志不能刷新设备状态。
- API、执行循环和任务监督共同执行运动门控。恢复操作不能绕过“停止未确认”；不将普通串口重连当成重新登记零点的许可。
- 发布工具纳入新增原生头文件；Python版本为0.3.0。包与构建记录保存在`outputs/resilience_20261126/`，未切换板端入口。

## 证据

完整回归共320项，无失败，8项跳过（6项可选CSRT、2项仅Linux用例）；见`outputs/resilience_20261126/final_regression.log`。新增故障及架构/发布重点回归25项全部通过，见`focused.log`。

重点覆盖：缺控制器而画面/检测继续、模型故障不关闭视频、相机断开而网页继续、缺标定仍能打开页面、Python视觉依赖缺失、串口只读无发送、回传过期、恢复后锁存、停止未确认拒绝恢复、任务阶段日志切换、请求令牌、资产缺失按组件隔离。C++通用IPC测试在本机编译并注入初始化异常、推理异常、崩溃和卡死，验证可重启及有限时间退出。

本机浏览器使用合成画面确认：摄像头/检测正常时，页面同时显示STM32不可用和A/B/C、四轮电机状态未知；恢复按钮禁用。点击重新检查后画面恢复，运动仍锁定，浏览器控制台未出现脚本错误。

`lint.log`记录静态与格式检查，`javascript_check.log`记录JavaScript语法检查，`wheel.log`和`package_check.json`记录wheel构建、必要资源覆盖和脱离工作区的导入验证。后者使用Python `-S`，不加载site-packages，确认界面外壳自身不依赖OpenCV/NumPy。

`source_manifest.json`记录本轮关键源码摘要。原有180条A/B决策对照和依赖方向约束继续纳入回归。

## 结果适用范围与下一步

上述证据支持本地软件故障隔离和恢复门控。视频、串口和控制器使用合成HTTP/PTY，原生测试针对通用IPC。完整C++视觉程序依赖RK3588的OpenCV、RKNN、GStreamer和显示环境，本轮没有完成其ARM构建，也没有访问真实相机、NPU或电机。

下一项最有价值的工作是：在现场具备条件后构建完整原生程序，先验收“仅板卡与摄像头”，再进行有人值守的通信断链和停止确认。具体清单见`follow_up.md`。

后续本地ARM构建与异常复核已完成，最新结果见[ARM复核记录](arm_review_20261126.md)。本文件保留首轮实现时的验证范围。

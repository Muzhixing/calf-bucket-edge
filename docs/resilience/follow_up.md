# 后续验收

本轮不连接无人值守现场、不部署、不运行电机。本地Linux ARM64完整构建与合成回放已经完成，见`arm_review_20261126.md`。下一步优先验证：在RK3588用“仅板卡与摄像头”的受控配置确认页面和真实模型检测常驻。

- 使用原已验证的SDK/OpenCV/GStreamer构建新原生程序，不能用旧二进制配上新Python包宣称本次功能完整生效。
- 验证只有板卡与摄像头：画面、检测可用；串口和机构状态说明准确，无运动命令。
- 验证缺模型、坏模型、坏标定、相机断开/接回、NPU阻塞；记录画面间隔、恢复时间及进程资源占用。
- 用模拟控制器完成应用层断链与禁用ACK测试后，再安排有人值守的实车故障恢复；确认不重复登记零点、不自动续跑。
- 完整行进到靠近阶段：验证串口所有权、阶段回传新鲜度、停止确认及前端状态一致。
- 若需要精确提示某台A/B/C或四轮电机缺失，先扩展固件在线诊断协议；现有回传不能推断该结论。

已有测试支持故障隔离的软件行为。真实NPU时延、摄像头重开、驱动退出时间及车辆停止状态由上述验收建立证据。

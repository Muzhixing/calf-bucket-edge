# 外观连续性与控制日志阻塞修复

## 命题与机制

新模型已连续检测到桶时，旧参考图的单次拒绝不应直接中断一个有连续当前画面证据的目标。当前候选增加独立的检测坐标外观对照：至少两次时序支持、当前唯一强检测≥0.8、上次已接受检测视图不超过120ms、检测框IoU≥0.55、去除边缘后的相邻灰度视图相关≥0.72且纹理标准差≥4，才能从光流失败转入`detector_continuity`。弱检测、多个近邻候选、空白遮挡、不匹配的新外观及过期视图不能启用这条路径。被拒绝的帧不会更新检测视图，最初锚点保持不变。

本次实测入口关闭同步CSRT，原可选实现保留用于独立对照。理由是新模型实录的配对回放中，CSRT没有增加成功定位，却产生数百毫秒长帧；不通过降低CSRT身份判断阈值换取速度。

`AsyncJournal`在单独写入线程完成JSON编码、文件追加和失锁截图。控制及视觉线程只提交有界队列，不在公共日志锁内等磁盘。队列拥堵先舍弃逐帧诊断样本，保留控制事件容量；关键队列满或写入失败令控制停用。关闭时限时排空并输出队列统计。控制线程限定CPU集合0/2，记录超过80ms的循环间隔，700ms真实回传超时门槛保持不变。停机后的界面现在使用`shutdown`结束后的回传，修正此前显示停机前旧A角度的问题。

## 本轮实机结果

用户完成左右移动、轻转、遮挡和居中静止，反馈“卡顿减少，两项暂停正常”。105.665秒实测记录2940个处理帧、501个使能目标命令，全部在A60–100/B0–96/C10范围内。系统与电机故障0、UART累计计数始终61，未出现`control_error`、回传超时或超过80ms的控制循环间隔；相邻串口读取记录最大263.7ms，上轮异常为722.7ms。

异步日志最大排队7项，样本和图片均无丢弃，最长写入19.73ms，正常排空退出。最后约13.96秒圈内保持期间没有发使能微调命令。录像确认完全遮挡时机构保持禁用，目标重新可见后恢复跟随；各失锁暂停段在收到禁用确认后均无使能命令。

这轮场景比固定录像变化更大，出现了桶明显改变距离、倾角和重现位置：仍有17段重获，最慢一段状态持续5.175秒，其中包含实际遮挡/目标离开和重新出现后的确认等待，不能把整段都算作可见误失锁。抽样画面约5285秒已重新检测到桶，至约5287.09秒才恢复追踪，提示大幅改变位置/尺度后的重获仍有优化空间。实机处理耗时中位33.02ms、P99 95.00ms、最大215.69ms（包括等待新图像及上层调度），不能用离线最慢66.45ms替代。当前已证实的是明显卡顿减少、未复现控制读取超时、两类暂停功能正常，并非全场景完全无停顿。

本轮已正常结束动作，独立只读复查全部为禁用、故障0，最终回传A77°、B83.9mm、C10mm，航向与零位位有效。未再次登记零位，未留下自动运行进程。修正版仍是独立测试入口；生产目录的新模型与原生程序、原启动入口未被覆盖。

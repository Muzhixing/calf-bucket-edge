# 现有 STM32 的一次性整机上电准备

本次路径只修改 RK3588 上位机，基于已验收追踪 main `38b2195`。保留现有 STM32，不烧录、不使用此前 CAN 回零反馈候选。检测模型、外观参考、重获、运动预测、遮挡暂停及圈内停止逻辑不变。

## 启动依据与行为

用户确认：整机彻底断电再上电后，现有机构会自主回到 A=90°、B 顶部、C 完全收回。本版把这个行为作为明确的操作约定；没有硬件回零完成信号。

在控制页“整机上电准备”中，操作者确认刚刚完成整机彻底断电再上电，且机构周围可安全运动。程序随后：

1. 根据已配置行程和有效回零速度计算等待时间。等待期间不打开控制串口、不发送运动命令。
2. 丢弃串口缓存，采集新的稳定回传；要求机构禁用、A90/B0/C0、B/C 尚未登记、航向有效、命令计数和 UART 错误计数稳定。这里的位置0仅作一致性检查，实际回零依据来自操作约定和等待。
3. 发一次原协议禁用帧，确认通信故障1已解除、没有电机等其他故障。其他故障不自动清除。
4. **先持久保存“本周期已尝试登记”，再发一次 SW2=06。** 等待命令计数、成功结果、两个零位位和禁用状态确认。不重复发送登记命令。
5. 发实际运动目标 A75/B0/C0。收到软件角度到位和禁用确认后，再发 A75/B0/C10；再次到位并停用确认。
6. 自动进入既有识别与追踪。A75 是下发的实际转动目标，不是把回传90改写成75；回传仍是软件进度，不构成实物位置测量。

上电准备本身是明确确认后执行的初始化动作，不以桶是否在画面内作为启动条件；“停止机构”随时取消准备。进入跟踪后的目标遮挡暂停与居中保持沿用原逻辑。原固件统一使能仍可能启用底盘航向保持，现场验收沿用已确认的底盘隔离/架空条件。

## 等待时间随范围计算

配置入口为 `deploy/serial_rx/arm_reference.json`。计算：

```
D_A = max(|A_min - 90|, |A_max - 90|)
D_B = max(|B_min|, |B_max|)
D_C = max(|C_min|, |C_max|)
T = ceil(max(5, 1.5 * (D_A/v_A + D_B/v_B + D_C/v_C) + 5)) 秒
```

A/B 范围直接读取 `operating_envelope.A_command_degrees`、`B_command_mm`，C 读取 `C_command_mm`（目前0～30，工作位置仍固定10）。当前对应最大回程30°、96 mm、30 mm。未确认三轴同时回零，因此按三轴时间相加；1.5倍及5秒是可配置的工程余量，不是已测得的设备参数。

`power_cycle_startup.homing_speed_floor` 的 `A_deg` 单位为度/秒，`B_mm`、`C_mm` 为相同机构坐标的毫米/秒；需要填写有依据的保守有效回零速度，并写入 `speed_evidence`。有效速度要覆盖启动、加减速和负载，不直接使用铭牌峰值。扩大已配置行程范围后，等待值自动重算，不另设固定延时。

**目前速度数值为空，因此整机初始化入口暂不放行。** 用户说明“最大速度回零”尚未提供可换算的速度。既有 STM32 的普通步进脉冲频率不能证明驱动器上电自主回零的速度；本次没有猜测速度。

计算只适用于断电前位置处于已配置范围的情况。其他程序或人工把机构移到范围外时，必须先扩大覆盖范围并核对机械边界；不能把追踪范围当成机械全行程。即使加了余量，电机卡滞/回零失败也不能通过等待本身检出，日志始终标记 `hardware_complete_signal=false`。

## 重启与重连规则

记录默认保存于 `~/.local/state/bucket-arm/power-cycle.json`，在所有录像/运行目录之外；`--startup-state` 可更改存储路径，但所有控制实例必须使用同一持久路径。删除记录不会自动初始化，只会回到未确认状态。

- 独占文件锁阻止第二个初始化实例；写入使用临时文件、原子替换、文件及目录 fsync。
- 每次操作者确认有唯一请求ID。相同请求重放、网络重试或双击不会再次登记。
- 等待、登记或运动阶段进程中断，下一次启动一律标为不确定，不自动续跑。即使未收到登记回传，也不能再次发送06。
- 已完成准备的记录可跨程序重启复用，但还必须通过原实时预检（禁用、零位/航向有效、工作范围、稳定命令计数），记录不能代替实机回传。
- 仅 STM32 复位时，实时零位位失效；普通追踪预检拒绝启动，不发送06。
- 串口重连不会创建新的整机周期。控制异常后保持停止；状态不确定时不会以重连触发重新登记。
- RK3588 `boot_id` 变化只会使历史记录失效，**不会授权回零**。文件损坏、存储失败同样不放行。
- 需要新一轮整机初始化时，必须确实完成整机断电再上电，再使用明确入口。新请求仍会检查实时零位位；已经登记的轴不能再次登记。

这实现的是“每个明确确认的周期至多尝试一次登记”，而非在通信中断时伪称一定成功。旧协议缺少整机电源周期标识，无法从零计数、串口恢复或单板启动自动辨认整机上电。

## 软件验证与部署边界

`tests/test_power_cycle.py` 使用伪终端和模拟 MCU，不连接物理串口。覆盖重复确认、进程重启、文件锁/损坏/fsync失败、等待未标定、范围扩展、初始零位已登记、登记ACK丢失、仅MCU复位、准备取消、实际A75/C10指令序列及完整自动跟随衔接。

专项18项、最终全套144项测试均通过，界面 JavaScript 语法检查通过。板卡 SSH `192.168.31.175:22` 本次连接超时，原复用套接字不存在；**尚未部署、未烧录、未实机运动，也没有宣称本轮已整机断电重启。**

待连接恢复后先备份并隔离部署候选：新增 `tracking/startup.py`，同步 `tracking/arm.py`、`runtime.py`、`index.html` 及 `serial_rx/arm_reference.json`，保留模型、标定与原生后端。首次运行只观察界面、配置和状态，不提交整机上电确认；补齐回零速度依据并核对范围后，再现场执行真实整机上电验收。

最有价值的下一项工作是记录覆盖最大回程的上电回零过程，得到三轴保守有效速度，并核对其终点。之后验收一次登记、A实际转75、C准备和程序重启不重复登记。

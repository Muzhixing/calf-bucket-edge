# 现有 STM32 的一次性上电与重启准备

本次路径只修改 RK3588 上位机，基于已验收追踪 main `38b2195`。保留现有 STM32，不烧录、不使用此前 CAN 回零反馈候选。检测模型、外观参考、重获、运动预测、遮挡暂停及圈内停止逻辑不变。

## 启动依据与行为

用户确认：整机彻底断电再上电后，现有机构会自主回到 A=90°、B 顶部、C 完全收回。2026-11-23 又逐轴确认仅重启 STM32 时 B 实际回顶部、C 实际完全收回，并说明 STM32 和电机共用供电、会一同重启。因此本机已确认的 STM32/电机重启也可使用同一流程；这不是从“共用电源”推导所有软件复位方式必然回零。本版把这个行为作为明确的操作约定；没有硬件回零完成信号。

在控制页“上电 / STM32 重启准备”中，操作者选择并确认刚完成整机重新上电，或本机已确认的 STM32/电机重启，且机构周围可安全运动。程序随后：

1. 默认等待 **8秒**：用户新提供的现场观察为“最长约5秒就结束”，加3秒工程余量。确认入口启动计时；不要求精确回零速度，不再使用60秒估算。
2. 等待期间相机/模型加载与真实推理预热、预览、跟踪线程、自检并行运行，并只读采集串口状态；不发送任何运动、禁用或零位登记帧。丢弃早期串口缓存，检查新的稳定回传：机构禁用、A90/B0/C0、B/C 尚未登记、航向有效、命令计数和 UART 错误计数稳定。位置0仅作一致性检查，回零依据仍是操作约定和等待。
3. 发一次原协议禁用帧，确认通信故障1已解除、没有电机等其他故障。其他故障不自动清除。
4. **先持久保存“本周期已尝试登记”，再发一次 SW2=06。** 等待命令计数、成功结果、两个零位位和禁用状态确认。不重复发送登记命令。
5. 发实际运动目标 A75/B0/C0。收到软件角度到位和禁用确认后，再发 A75/B0/C10；再次到位并停用确认。
6. 清除准备前锁定坐标、重建跟踪器，等待准备完成后收到的新画面重新确认目标，再自动进入既有识别与追踪。等待期间的候选和图像仍用于视觉预热及观察，不直接驱动准备后的机构。A75 是下发的实际转动目标，不是把回传90改写成75；回传仍是软件进度，不构成实物位置测量。

上电准备本身是明确确认后执行的初始化动作，不以桶是否在画面内作为启动条件；“停止机构”随时取消准备。进入跟踪后的目标遮挡暂停与居中保持沿用原逻辑。原固件统一使能仍可能启用底盘航向保持，现场验收沿用已确认的底盘隔离/架空条件。

## 8秒等待与并行预热、自检

相机/模型服务在程序启动时就开始运行，等待期间持续执行真实推理。累计10个递增帧号、有效NPU推理耗时的原生结果作为预热检查，不要求画面里必须有桶；重复帧不能充数。还检查新鲜相机帧、跟踪处理帧、预览、标定参数、日志线程及原生进程存活。

准备放行需要同时满足“8秒已到”和“必要自检通过”，总等待取二者较晚完成的时间，不串行叠加8秒和预热时间。串口预检也在这段时间中只读采集。相机启动较慢或等待期短暂失败会继续等待恢复；开始运动后失去自检条件则停止。界面区分“等待整机回零”和“等待模型或机构自检完成”。

## 行程扩展时的估算

配置入口为 `deploy/serial_rx/arm_reference.json`。计算：

```
D_A = max(|A_min - 90|, |A_max - 90|)
D_B = max(|B_min|, |B_max|)
D_C = max(|C_min|, |C_max|)
scale = max(1, D_A/30, D_B/96, D_C/30)
T = ceil(5 * scale + 3) 秒
```

A/B 范围直接读取 `operating_envelope.A_command_degrees`、`B_command_mm`，C 读取 `C_command_mm`（目前0～30，工作位置仍固定10）。当前对应最大回程30°、96 mm、30 mm，计算得到8秒。5秒观察值、3秒余量及范围参考值均可配置。

`power_cycle_startup.observed_home_max_s=5`、`settle_margin_s=3`，`reference_return_distances` 记录本次配置的范围参考。扩大范围时按最大相对比例延长5秒部分，余量不缩减；这是一种后续可实测校正的估算，不是精确运动模型。

**不再以缺少精确速度阻止初始化。** 用户观察的约5秒优先于普通脉冲运动速度外推。范围参考值也不是“用户已在每个端点测过5秒”的证据，不宣称8秒覆盖所有未经测试的行程或误差已验证为1秒。

计算只适用于断电前位置处于已配置范围的情况。其他程序或人工把机构移到范围外时，必须先扩大覆盖范围并核对机械边界；不能把追踪范围当成机械全行程。即使加了余量，电机卡滞/回零失败也不能通过等待本身检出，日志始终标记 `hardware_complete_signal=false`。

## 重启与重连规则

记录默认保存于 `~/.local/state/bucket-arm/power-cycle.json`，在所有录像/运行目录之外；`--startup-state` 可更改存储路径，但所有控制实例必须使用同一持久路径。删除记录不会自动初始化，只会回到未确认状态。

- 独占文件锁阻止第二个初始化实例；写入使用临时文件、原子替换、文件及目录 fsync。
- 每次操作者确认有唯一请求ID。相同请求重放、网络重试或双击不会再次登记。
- 等待、登记或运动阶段进程中断，下一次启动一律标为不确定，不自动续跑。即使未收到登记回传，也不能再次发送06。
- 已完成准备的记录可跨程序重启复用，但还必须通过原实时预检（禁用、零位/航向有效、工作范围、稳定命令计数），记录不能代替实机回传。
- MCU 复位后实时零位位失效时，普通追踪预检拒绝启动并使旧准备记录失效，不自动发送06。“记录 STM32 已重启”入口也可立即停用旧准备状态，不会自动登记；随后明确确认本机已知的 MCU/电机重启事件，重新走8秒准备流程。没有监测串口时无法自动发现复位，必须使用明确入口。
- 串口重连不会创建新的整机周期。控制异常后保持停止；状态不确定时不会以重连触发重新登记。
- RK3588 `boot_id` 变化只会使历史记录失效，**不会授权回零**。文件损坏、存储失败同样不放行。
- 需要新一轮初始化时，必须确实完成上述一种已确认的重启，再使用对应入口。新请求仍会检查实时零位位；已经登记的轴不能再次登记。

这实现的是“每个明确确认的周期至多尝试一次登记”，而非在通信中断时伪称一定成功。旧协议缺少整机电源周期标识，无法从零计数、串口恢复或单板启动自动辨认整机上电。

## 软件验证与部署边界

`tests/test_power_cycle.py` 使用伪终端和模拟 MCU，不连接物理串口。覆盖重复确认、进程重启、文件锁/损坏/fsync失败、8秒默认值、范围扩展、初始零位已登记、登记ACK丢失、仅MCU复位、准备取消、实际A75/C10指令序列及完整自动跟随衔接。新增并行等待、自检较慢、推理预热计数和相机启动恢复检查。

板卡 SSH `192.168.31.175:22` 本次连接超时，原复用套接字不存在；**尚未部署、未烧录、未实机运动，也没有宣称本轮已整机断电重启。** 本版完整回归167项通过（98.464秒），其中启动流程25项、诊断及重启入口16项；UI JavaScript 语法与 git diff --check 通过。详见交付测试日志。

待连接恢复后先备份并隔离部署候选：新增 `tracking/startup.py`，同步 `tracking/arm.py`、`runtime.py`、`index.html` 及 `serial_rx/arm_reference.json`，保留模型、标定与原生后端。首次运行只观察界面、配置和状态；随后在真实整机上电后使用明确入口，直接按8秒默认等待进行现场验收，无需先标定精确速度。

现场验收重点：等待结束前机构是否已经停稳；模型/自检较慢时是否继续等待；B/C仅登记一次；A实际转75、C准备及自动追踪是否正常；程序重启或串口重连是否未重复登记。用这轮观察校正等待值，不要求先取得三个精确速度。

## 8秒内的附加诊断

附加诊断从操作确认时开始收集，在8秒（或扩大范围后的配置窗口）结束时冻结并显示简短结果；不追加固定采样等待，不参与新的运动放行条件。必需就绪检查仍决定是否能准备。异常、样本不足和可选数据不可获得分别记录；本阶段不更新原生后端或 STM32。

- 延迟：每项提供样本量、P95、最大值及超过阈值的次数。取帧是本机 HTTP 拉取 BGR 的耗时（含等待/拷贝）；推理使用原生 NPU 耗时；跟踪和预览测量各自处理耗时。原生 read 完成到发布的间隔只相减两个原生时钟值；BGR 收到至跟踪/JPEG 完成只相减同帧上位机单调时钟。没有相机曝光时间和浏览器呈现时间，不报告完整端到端延迟。
- 连续性：统计递增帧号、原生时间间隔、倒退/重复、窗口末尾长时间无新帧和取帧错误。latest-only 管线跳过帧号单独标记，不能据此断言相机丢帧。每秒最多4次低分辨率亮度/细节采样；低细节只能提示“低纹理或模糊”，不作为断流或停止条件。
- 解码：可观察到 BGR 长度、元数据和取帧异常；当前原生后端未导出 MJPEG 解码错误计数，明确标记不可获得，不伪称零错误。传感器采集/解码分段耗时也未暴露。
- 串口：按主机读取批次统计间隔，共读多帧单列，不能给批内帧虚构独立到达时刻。报告解析器校验/版本/帧尾错误；UART 初始值与窗口内新增分开。小幅向上增长可计新增；下降、可能回绕或零位标志丢失分开记为歧义/状态失效，不将255→0当作255个错误或真实回零证明。
- 并行只读基线：磁盘空闲、可读的 MemAvailable、温度和当前 CPU 频率；频率低不等于降频，可靠降频标志缺失时如实标记。读取原生 binding.json 的模型/标定哈希，与现有固定模型及启动标定参数比较，检查运动配置能容纳 A75/B0/C10。原生已有单类别输出形状校验，binding不含语义类别名称，不能据此验证训练标签含义。基线线程迟到不延长窗口。
- 无桶不是失败：统计已观察到的候选帧数，准备动作后强制使用新画面重新建锁。

诊断阈值仅用于定位问题：取帧/原生发布/收到图像后处理延迟100ms；NPU、跟踪和预览处理50ms；相机交付帧间隔100ms、串口批次375ms。窗口结束相机超过400ms无新帧、串口超过700ms无新回传单列异常。少于5个样本标为样本不足，高分位只是该启动窗口的描述，不是长期性能保证。详项事件为 `startup_diagnostics_result`。

# 正左对齐后的模型辅助测距与左移

用户要求保留原先前进追踪，在桶位于车体左侧后使用模型辅助测距并左移，距离20cm时停止。用户确认20cm指相机到桶身，不是车身外沿净空。实现使用双目光心中点到所选桶身表面的欧氏距离；实体镜头前沿与光心的偏移尚未测定，不能宣称已获得精确车身净空。

## 流程与停止条件

`track_forward_probe.py` 的原前进追踪、A限幅和132°左视参考保留。新增可选模型参数，只有 `left_reference_reached` 且串口确认禁用停车后才交接到 `side_approach.py`。到时停止、丢失目标、仅触及A边界或禁用未确认都不进入左移。前后阶段串行持有串口，不并发发送命令，不重新登记B/C零点。

左移阶段固定A及B/C收回姿态，锁定同一目标：

1. 静止采集同帧原始双目图和检测元数据。
2. 在桶身内区域进行256原尺寸视差范围的传统双目匹配，检查左右一致性、纹理、有效支持与距离分布。传统结果无效才调用冻结Fast-ACVNet补测，同样经过左右一致性和支持检查。
3. 距离大于停止边界时以8%左移0.6秒，收到禁用回报后静置0.3秒，再采新图复测。模型计算全程输出禁用。
4. 距离中位数≤20cm立即结束；有效像素P10距离≤21cm时按1cm停止余量提前结束。后者必须记为 `distance_stop_margin`，不能记成精确到达20cm。
5. 测距无效、异常跳变、目标切换/丢失/部分出画、左对齐丢失、航向偏差>3°、串口异常或复位特征均结束。不会使用最后一次有效距离盲走，也不会自动右移或重启流程。

单段累计左移动作上限10秒（0.6秒步长，最多9.6秒），整个左移阶段上限90秒。这些是任务限时，不代表有电池电量回传。未达到20cm而预算用完时单独报告，不续跑整条投喂路线。B/C必须已按实际位置登记；没有自动登记、伸C或出料代码。

正常图像新鲜度上限0.5秒。模型可能耗时数秒：仅在每次串口检查均保持禁用、目标框IoU≥0.97且固定区域像素NCC≥0.97的静止测量中，允许原始测量帧最多5秒。该静止条件不成立就拒绝结果。运动期间不扩展图像时限，每次短移后必须用停车后的新图。

## 板端适配

引用侧对话的原模型，不训练、不改变权重：

- 模型：`research/stereo_phase4_20261125/compilation/full_rewritten/full/model.rknn`。
- 模型SHA256：`6f3e86c00b6ba3dc63a9d6d7b070d6502b721d2e5ac1eb4f11087ced1b9405ac`。
- 标定SHA256：`5917ede19309a4f78d810b3c9c91d4e8033c23751307e6879f7e3f55f5c7031e`。
- 缩放到640×360，RGB与ImageNet归一化，顶部24行补零，双向推理及1工作像素左右一致性检查。

首次板端RKNNLite试推理发现系统runtime2.1.0不支持CPU GridSample，随后崩溃；私有2.5.0库也未直接解决旧图的CPU算子。依据[官方自定义算子接口](https://github.com/airockchip/rknn-toolkit2/blob/v2.3.2/rknpu2/runtime/Linux/librknn_api/include/rknn_custom_op.h)，新增固定模型专用CPU双线性GridSample回调，保持原图的zeros边界和align_corners=true。只接受该冻结模型中的两种张量形状；非法形状、非有限值与内存布局会拒绝。通过C接口调用RKNN并注册回调，Python不再走已知会崩溃的默认推理入口。

运行库与桥接库位于独立的 `/home/elf/deploy/assisted_approach_20261125/runtime_latest/`；未替换 `/usr/lib/librknnrt.so`。检测程序继续使用原系统库，测距进程单独加载私有库。原生视觉只新增 `/capture.sbs.bgr`，同一个不可变Packet同时返回左右原图、帧号和检测元数据；原检测、前期测距和显示逻辑不变。

## 使用入口与回退

经备份与前置哈希核对后，将已验证的原生二进制、新双目接口、辅助模块及控制入口安装到 `/home/elf/deploy/vision_cpp/` 与 `/home/elf/deploy/serial_rx/`。具体前后哈希与回退文件见独立目录的 `deployment.json` 和 `backups/production_before/`。系统运行库未更换，没有启动控制进程。

板端独立目录保持 `deploy/vision_cpp`、`deploy/serial_rx` 布局。固定相机视觉应使用该目录新编译的 `vision`，传入原生产检测模型、标定及assets，监听8899；不要用会自动启动机械臂自检的旧 `run.sh` 代替。

`sh deploy/serial_rx/run_assisted_forward.sh` 添加模型及标定参数，其余参数与原 `track_forward_probe.py` 相同，包括 `--reference`、`--left-reference`、`--calibration`（YAML）、`--seed-image`、`--seed-box`、`--expect-a`、`--seconds`、`--out`。初始种子仍须来自本次画面，不能拿旧桶图片直接启动。

单独左移阶段可用 `side_approach.py`；默认只观察，显式 `--execute` 才访问控制串口。必须设置 `BUCKET_ACV_BRIDGE` 指向私有 `libfastacv.so`，并提供当前种子和已确认的左视姿态。不能在已有控制器运行时另开串口拥有者。

本轮不修改开机服务，不自动运行路线。回退时从 `backups/production_before/vision_cpp/vision` 恢复原生产二进制，并使用不带辅助测距参数的前进控制器；原生产文件的回退副本在独立目录；模型和私有运行库也保存在该目录，不需要回刷STM32。
